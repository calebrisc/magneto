# Ear meshes for the IEM try-on pipeline

**This directory is gitignored.** Nothing under `cad/iem/ears/` is committed —
the meshes belong to their original publishers and are several GB. Re-fetch
with `python fetch_ears.py --source all --n 45` from `cad/iem/` (inside
`.venv`), then rebuild the synthetic corners with
`python make_synthetic_ear.py`.

```
ears/
  hutubs/     "3D head meshes"/ppN_3DheadMesh.ply   (metres)
  sonicom/    PXXXX_preprocessed.stl                (mm)
  synthetic/  xs_shallow / xs_deep / xl_shallow / xl_deep .stl + landmarks_truth.json
  aligned/    per-ear JSON + cached patch PLY + QC PNG, written by align_ear.py
```

## HUTUBS (TU Berlin) — 58 head meshes released of 96 subjects

* Landing page: <https://depositonce.tu-berlin.de/items/dc2a3076-a291-417e-97f0-7697e332c960>
* DOI: <http://dx.doi.org/10.14279/depositonce-8487>
* **Licence: CC BY 4.0** (`dc.rights.uri = https://creativecommons.org/licenses/by/4.0/`).
  Attribution required; commercial use and derivatives permitted.
* **Scriptable.** The site is a DSpace 9 Angular front end, but its REST API is
  on a *different host* — `https://api-depositonce.tu-berlin.de/server` — which
  the front end publishes in `assets/config.*.json` under `rest.baseUrl`.
  Hitting `/server/api/...` on the www host returns the Angular 404 page, which
  is the only trap here. From the item UUID:

  ```
  GET /server/api/core/items/<uuid>/bundles          -> find the ORIGINAL bundle
  GET /server/api/core/bundles/<uuid>/bitstreams     -> find "3D head meshes.zip"
  GET /server/api/core/bitstreams/<uuid>/content     -> 149 MB, all subjects
  ```

  There is nothing per-subject to iterate: one zip holds every mesh.
* **Contents.** `ppN_3DheadMesh.ply`, ~283 k faces, watertight, **in metres** —
  `fetch_ears.py` / `earfit.py` scale by 1000. Head only, no torso, hair
  removed. Pinna captured at 0.05 mm with an Artec Space Spider and merged into
  the head mesh, which is why HUTUBS has the best concha detail of the two sets.
  Only 58 of the 96 subjects have a mesh in the archive.

**Cite as:** Brinkmann, F., Dinakaran, M., Pelzer, R., Grosche, P., Voss, D.,
Weinzierl, S. *The HUTUBS head-related transfer function (HRTF) database.*
DOI 10.14279/depositonce-8487 (also: *A Cross-Evaluated Database of Measured and
Simulated HRTFs Including 3D Head Meshes, Anthropometric Features, and Headphone
Transfer Functions*, JAES 67(9), 2019).

## SONICOM (Imperial College London) — 200+ subjects, 45 fetched

* Browsable at <https://transfer.ic.ac.uk:9090/#/2022_SONICOM-HRTF-DATASET/>
* Project: <https://www.axdesign.co.uk> (Audio Experience Design, Dyson School
  of Design Engineering). Dataset information sheet:
  `/Information/SONICOM_Dataset_Information_Sheet.pdf` on the same server.
* **Licence: check the information sheet before redistributing.** The download
  is open and unauthenticated, and the dataset is published for research use,
  but the server does not state a machine-readable licence and the sheet is the
  governing document. Treat it as research-use, attribution-required, and do
  **not** redistribute the meshes — hence the gitignore. Human-subject scans:
  do not attempt re-identification.
* **Scriptable, with a wrinkle.** The site is a CrushFTP `WebInterface`; the
  `#/...` URLs are client-side routes and fetching them returns an empty body.
  The backend, however, exposes an unauthenticated JSON listing endpoint:

  ```
  POST https://transfer.ic.ac.uk:9090/WebInterface/function/
       command=getXMLListing&format=JSONOBJ&path=/2022_SONICOM-HRTF-DATASET/
  ```

  and files are then a plain `GET` on their path. The host serves a chain the
  Python stdlib store rejects on macOS, so `fetch_ears.py` uses an unverified
  SSL context for this host only (public data, no credentials).
* **Which file to take.** Each subject has three useful meshes:

  | path | size | notes |
  |---|---|---|
  | `3DSCAN/PXXXX.stl` | ~100 MB | raw head **and torso**, arbitrary pose, holes |
  | `3DSCAN/PXXXX_watertight.stl` | ~61 MB | same, patched |
  | `SYNTHETIC_HRTF/PXXXX_preprocessed.stl` | **~18 MB** | **what we use** |

  `_preprocessed` is aligned to the Frankfurt plane, beheaded, smoothed and
  de-haired — consistent orientation across subjects for free. Crucially it is
  *not* `_plugged.stl`, which has the canal entrance filled in; we need the
  canal mouth open. 10 of 55 attempted subject IDs 404 or time out (the ID
  range has gaps, e.g. P0253, P0258, P0270); `fetch_ears.py` skips and reports
  them, so ask for more subjects than you need.

**Cite as:** Engel, I., Daugintis, R., Vicente, T., Hogg, A. O. T., Pauwels, J.,
Tournier, A. J., Picinali, L. *The SONICOM HRTF Dataset.* Journal of the Audio
Engineering Society 71(5), 2023.

## Synthetic corner ears

Generated by `make_synthetic_ear.py`, not downloaded. Four parametric ears at
the corners of the `docs/EAR_ANTHROPOMETRY.md` envelope (aperture 7 × 4.5 mm vs
18 × 14 mm, concha depth 8 mm vs 18 mm) written in the same head frame as the
scan datasets, plus `landmarks_truth.json` with the exact aperture centre and
canal axis for scoring the detector. These exist because the two scan sets are
European-recruited university populations and do not reliably contain the tails
of the envelope.

---

## Head frame (both scan datasets, verified by inspection)

`+x` anterior (nose is the max-x vertex), `+y` toward the **left** ear, `+z`
superior. The **right** ear — the one the master STLs are cut for — is at
**-y**, and its lateral/outward direction is `-y`. HUTUBS is in metres,
SONICOM in millimetres; `earfit.DATASETS` carries the scale factor.

## Manual landmarking fallback

`align_ear.py --qc-png` writes `aligned/<dataset>_<id>_<side>_qc.png`: the
hull-relative depth map with the detected aperture and tragus marked. If a pick
is wrong, write a JSON of overrides and pass `--landmarks`:

```json
{"P0007": {"aperture": [-1.2, -64.0, 1.8], "floor_normal": [0.1, -0.98, 0.05]}}
```

Coordinates are in the scan's own frame (mm, after the dataset scale factor).
The easiest way to read one off is to open the cached
`aligned/<...>_patch.ply` in MeshLab and pick the point at the canal mouth.
